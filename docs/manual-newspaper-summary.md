# 관리자 신문 다운로드·요약

신문 요약 화면의 신문 원본 영역에서 관리자에게만 세 버튼을 표시한다.

- **다운로드·요약**: 시간 제한 없이 카페 수집기를 한 번 실행하고 웹 캐시에 연결한 뒤 실제 요약을 실행한다.
- **다운로드만**: 수집과 캐시 연결까지 실행한다.
- **요약만 실행**: 이미 준비된 오늘 지면을 읽는다. 캐시가 없으면 다운로드된 파일을 동기화한다. 카페 수집기는 실행하지 않는다.

한국시간 오늘 신문만 처리한다. 수집 실패, 파일 없음, 게이트웨이 설정 없음, 요약 실패는 완료로 표시하지 않는다. 실행 중 연타·별도 프로세스의 중복 실행을 막는다. 진행 상황은 3초마다 확인하며 지면 번호를 표시한다. 화면을 닫아도 서버에서 계속 실행한다.

## 실제 요약 연결

기존 OpenClaw 게이트웨이의 `GATEWAY_TOKEN`을 사용한다. `NEWS_REDO_GPT_MENTION`과 Slack 봇 멘션은 사용하지 않는다. Slack에 부탁 메시지를 보내는 단계를 실제 지면별 요약과 웹 게시로 교체했다. 이 작업은 Slack 메시지를 보내지 않는다.

선택 설정:

- `NEWS_SUMMARY_GATEWAY_URL`: 기본은 기존 `MER_GATEWAY_URL`, 없으면 `http://127.0.0.1:18789/v1/chat/completions`
- `NEWS_SUMMARY_AGENT`: 기본은 기존 `MER_SUMMARY_AGENT`, 없으면 `openclaw/debate-gpt`

에이전트는 이미지 입력과 JSON 응답을 지원해야 한다. 원본 지면 사진을 사용하며, PDF만 있는 경우 PyMuPDF가 필요하다. 본문 수치를 유지하고 WHAT·WHY·HOW(구체적인 내용)와 기사별 지면 연결 정보를 생성한다. 광고 전용 지면은 명시적으로 제외한다. 판독 실패나 날짜 불일치 시 게시하지 않는다.

`NEWS_CACHE_DIR/YYYY-MM-DD/.summary_pages/`에 이미지 해시별 완료 지면을 기록해 재시도 때 이어서 처리한다. 전체 완료 후 `manual_summary.json`을 원자적으로 교체하고 `/economy/data`에 연결한다. 진행 상태는 캐시 루트 `.manual-job.json`에 보존한다. 서버 재시작으로 중단되면 요약만 실행해 이어갈 수 있다. 계정별 책갈피·지면 표시는 변경하지 않는다.

## 이번 누락분 1회 실행

사용자가 요청한 **2026-11-09** 요약은 이 버전이 해당 날짜(KST)에 배포되어 웹 서버가 시작되면 받은 파일로 한 번 실행한다. 날짜가 지나면 실행하지 않는다. `.recovery-2026-11-09.started`가 재시작 때의 반복 실행을 막는다. 기존 예약 작업은 활성화하거나 변경하지 않는다. 실제 성공 여부는 관리자 진행 상태와 기사 표시에서 확인한다. 실패 시 관리자 버튼으로 다시 실행할 수 있다.

## 검수 요약 게시 및 수동 실행 재확인

2026-11-09 PDF 30쪽을 직접 읽고 작성한 34개 기사·사진기사 요약을 사용자 요청으로 `news_published.py`에 게시한다. 30쪽은 기사 없는 이미지로 제외했다. 해당 날짜에 완성된 서버 요약이 없으면 `/economy/data`가 이 게시본을 제공한다. 완성된 새 요약이 있으면 새 요약을 우선하며, 다른 날짜에는 이 게시본을 표시하지 않는다. 서버 재기동마다 표시 시각이 바뀌지 않도록 게시 시각을 고정했다. 이 콘텐츠는 서버 자동 요약 성공을 의미하지 않는다.

수동 요약에서 판독·분류 응답이 불완전한 지면은 전체 이미지와 겹치는 네 부분 이미지로 한 번 더 읽는다. 재시도에도 실패하면 해당 쪽을 표시하고 중단하며 이전 게시본은 유지한다. 광고와 기사 없는 장식 이미지는 명시적으로 제외하지만, 읽기 실패를 기사 없음으로 간주하지 않는다. 모든 지면 완료 후 저장한 파일을 다시 읽어 메시지와 기사 수가 일치하는지 확인한다. 실제 운영 게이트웨이의 응답 성공은 운영 서버에서 확인해야 한다.
