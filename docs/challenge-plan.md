## 5. 챌린지 화면 (`/challenge`, 새 파일 `stock/challenge_view.html`)

1. **맨 위 탭**: 역할에 맞게 서버가 만들어 넣는다(아래 6-3).
2. **머리 영역**: `1기 · 11/3 ~ 11/28 · 진행 12/20일` + 평일 달력 줄(✅ 완료 / ✗ 빠짐 / ⭕ 오늘 / · 남은 날 / – 신문 없음).
3. **오늘 신문 사진 바둑판**: 썸네일 30장(폰 3열 · PC 6열), 내가 이미 쓴 장은 ✅, 다른 찰스가 쓴 장은 작은 숫자 배지.
   - 신문이 아직 안 올라왔으면(보통 05~07시): "오늘 신문이 아직 도착하지 않았어요" + 자동 새로고침.
   - 주말: "오늘은 쉬는 날이에요 🌿" + 지난 기록 보기.
4. **사진을 누르면**: 큰 사진(두 손가락·휠 확대) + 입력칸 4개 + [저장]. 저장 중 끊겨도 쓰던 글은 이 브라우저에 임시 보관(새로고침해도 안 날아감).
5. **같은 기수 글**: 날짜별로 닉네임 · 사진 번호 · 4칸 내용. 사진 번호를 누르면 그 사진이 열림.
6. **지난 날**: 달력에서 날짜를 누르면 그날 사진·글을 읽기 전용으로.
7. **완수 팝업**: 마지막 의무일 글을 저장하는 순간(또는 그 뒤 첫 접속) 한 번만 —
   🎉 꽃가루 + **"꾸준함은 인생을 바꿀 수 있습니다"** + "이제 모든 화면을 이용할 수 있어요" [신문 요약 보러 가기].

## 6. 서버 설계 (기술 상세)

### 6-1. 저장소(데이터베이스)
기존 `~/.openclaw/secret/gate/gate.sqlite` 에 표를 추가한다(예전 DB도 자동으로 칸 추가 — 지금 방식 그대로).

```sql
-- 사용자 표에 칸 추가
users.role          TEXT    -- NULL=일반, 'charles'=찰스, 'graduate'=완수자
users.cohort_id     INTEGER -- 소속 기수
users.celebrated_at TEXT    -- 축하 팝업을 본 시각(한 번만 보이게)

CREATE TABLE cohorts(
  id INTEGER PRIMARY KEY, name TEXT UNIQUE NOT NULL,
  start_date TEXT NOT NULL, end_date TEXT NOT NULL, memo TEXT, created_at TEXT NOT NULL);

CREATE TABLE challenge_posts(
  id INTEGER PRIMARY KEY, user_id INTEGER NOT NULL, cohort_id INTEGER,   -- 관리자 글은 cohort_id NULL(=전체 공개)
  day TEXT NOT NULL,            -- 신문 날짜 YYYY-MM-DD
  page TEXT NOT NULL,           -- 사진 파일 이름(예: 07.jpg)
  what TEXT, why TEXT, how TEXT, think TEXT,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
  UNIQUE(user_id, day, page));  -- 같은 사진엔 한 사람당 글 1개(다시 저장하면 수정)

CREATE TABLE challenge_excused(            -- 관리자가 '인정'한 날
  user_id INTEGER, day TEXT, by_admin INTEGER, at TEXT, PRIMARY KEY(user_id, day));
```

- **탈퇴·삭제 시 그 사람의 글·인정 기록도 함께 삭제**(`delete_user` 확장).

### 6-2. 화면·데이터 주소(API)
| 주소 | 하는 일 | 권한 |
|---|---|---|
| `GET /challenge` | 챌린지 화면 | 찰스·완수자·관리자 |
| `GET /api/challenge/me` | 내 기수·기간·진행도·달력·완수 여부·팝업 필요 여부 | 〃 |
| `GET /api/challenge/day?date=` | 그날 사진 목록 + 내 글 + 같은 기수 글 | 〃 (관리자는 `&cohort=`) |
| `GET /api/challenge/photo?date=&name=&thumb=1` | 신문 사진(챌린지 전용 통로) | 〃 |
| `POST /api/challenge/post` | 글 저장·수정(오늘만, D3) | 찰스·관리자 |
| `POST /api/challenge/celebrated` | 팝업 봤음 기록 | 본인 |
| `POST /gate/admin/act` (기존) | `charles_on/off`, `cohort_*`, `excuse` 동작 추가 | 관리자 |

- 찰스는 `/api/news/*` 가 막히므로(D11) 사진은 **`/api/challenge/photo`** 로만 받는다(내부에선 기존 `news_files.resolve` 를 그대로 써서 안전한 이름만 허용).

### 6-3. 권한 규칙(문지기 `_check` 확장)
- 잠그는 주소에 `/challenge`, `/api/challenge/*` 추가.
- 역할별 허용:
  - 찰스: `/dig`, `/api/dig/*`, `/challenge`, `/api/challenge/*`, `/gate/*` 만. 그 밖은 화면이면 `/challenge` 로, API 면 403.
  - 일반: 지금과 같음, `/challenge` 는 막음(완수자·관리자는 열림).
- 로그인 뒤 기본 도착지: 찰스 → `/challenge`, 그 외 → `/economy`(`safe_next` 허용 목록에 `/challenge` 추가).
- **맨 위 탭을 한 곳에서 만들기**: 지금 4개 HTML 파일에 같은 탭이 복사돼 있다 → `<!--GATE_NAV-->` 자리로 바꾸고 `gate.nav_html(request, current)` 가 역할에 맞는 탭만 넣는다(앞으로 탭을 고칠 때 한 곳만 수정).

### 6-4. 완수 판정(가장 중요한 규칙)
```
의무일 = 기수 기간 안의 평일 중, 신문 사진이 올라온 날(D4)  ※ 오늘·미래는 '아직'
그날 완료 = 그날(밤 12시 전) 저장한 글 ≥ 1개(D1) 또는 관리자 '인정'
완수 = 기수 종료일까지의 의무일이 모두 완료
```
- 완수 판정은 **글을 저장할 때**와 **/api/challenge/me 를 부를 때** 계산한다(따로 예약 작업 불필요).
- 마지막 평일에 신문이 안 올라오는 경우(휴간)도 종료일이 지나면 판정되도록 "종료일이 지났는가"를 함께 본다.
- 완수되면 한 번에: `role='graduate'`, `expires_at=NULL`(무기한), `status='approved'` → 다음 화면부터 모든 탭.

### 6-5. 사진 보관 기간 문제 ⚠️
- 지금 신문 사진(`news_cache`)은 **14일 뒤 자동 삭제**(`retention_cleanup.py`) → 지난 챌린지 날의 사진이 사라진다.
- ✅ 해결: 찰스가 글을 쓴 장은 **작은 사진(썸네일)을 챌린지 폴더에 복사**해 두고 기간 + 30일 보관(글은 계속 남음).
  다른 선택지: 챌린지 진행 중엔 `news_cache` 보관을 60일로 늘리기(디스크 사용 증가).

### 6-6. 개인정보·보안
- **처리방침 수정**: 새로 저장하는 정보(기수, 작성 글, 진행 기록)를 추가하고 "같은 기수 참가자에게 닉네임과 글이 공개됨"을 명시 → `POLICY_VERSION` 을 올림 → **전원 재동의 1번**.
- 글은 화면에 넣을 때 모두 HTML 이스케이프(남이 쓴 글로 해킹 코드 실행 방지).
- 저장·수정은 **본인 글만**, 다른 사이트에서 온 POST 거부(기존 규칙), 칸 길이 제한, 같은 사람의 1분 30회 이상 저장 거부.
- 다른 기수 글은 API 단계에서 걸러냄(화면에서 숨기는 게 아니라 아예 안 보냄).

### 6-7. nginx (사용자가 서버에서 1번)
`location ~ ^/(economy|slack|dig|gate|privacy)(/|$)` 에 **`challenge`**(그리고 아직 없다면 **`ai`**) 추가,
`location ~ ^/api/(dig|news)/` 에 **`challenge`**(그리고 **`ai`**) 추가 → `sudo nginx -t && sudo systemctl reload nginx`.

## 7. 만드는 순서

### 1단계 — 바로 써 볼 수 있는 최소판 (이번에 만들 것)

6. 처리방침 문구 추가(`POLICY_VERSION` 올림)
